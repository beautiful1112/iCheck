## Acceptance order

1. **Control-plane identity** — log in through the configured local exchange or
   enterprise OIDC path; verify tenant/region and scoped roles.
2. **Device onboarding** — add all lab devices in the GUI, verify duplicate IP,
   invalid target, cross-site, and disabled credential failures.
3. **Connection preflight** — prove network reachability and protocol response
   through the intended site Worker; a control-plane-host test is insufficient.
4. **Activation** — review the deterministic deployment plan/hash, approve it,
   and verify exact-version deployments and runtime health.
5. **Collection** — observe successful Collector runs and normalized envelopes;
   force one failure and recovery without deleting history.
6. **Identity and topology** — open `/assets/endpoints` and `/topology`; verify
   MAC/IP, wired attachment, Wi-Fi sessions, LLDP/CDP edges, scope filtering,
   stale-state closure, and no raw vendor payloads.
7. **Metrics and logs** — register Prometheus and Loki at
   `/settings/observability` with the lab's real authentication policy; verify
   health plus instant/range Prometheus evidence. Open `/logs`, confirm
   Device-selector construction, out-of-scope denial, line/label and upstream
   credential redaction, bounds, and hash-only audit. Revise one backend,
   verify stale-revision rejection and health invalidation, disable it from the
   GUI, and confirm queries fail closed until it is re-enabled and rechecked.
8. **AI settings** — configure provider URL, model names, secret reference,
   route budgets/fallbacks, and Agent Profile placement/tool policy through the
   settings pages. No token is pasted into an investigation.
9. **Agent loop** — start an Investigation from `/`; require at least two model
   iterations with different typed Tools, persisted evidence, a defensible
   conclusion or explicit escalation, and no credential/raw configuration in
   model context or audit.
10. **Active diagnostics** — let the Agent propose
    `windows.request_diagnostics`; verify independent approval, checkpointed
    resume, exact preconfigured operation set, idempotent queueing, Worker run,
    and later `windows.get_latest_diagnostics` consumption.
11. **Situation intelligence** — create real Alerts, correlate a Situation,
    inspect evidence timeline/service impact/topology paths, and confirm the
    product does not present topology adjacency as proven root cause.
12. **Capability Studio** — author or revise one sanitized API Collector, one
    Skill or Workflow, and one topology view in-product; validate/preview,
    publish through governance, activate, and retain immutable provenance.
13. **Failure recovery** — restart PostgreSQL and the API/Workers during leased
    work; verify checkpoint resume, lease reassignment, idempotency, cancellation,
    and no duplicate state-changing execution. A private, restricted-role
    Agent Worker SIGKILL probe (private development evidence; not distributed)
    passed with two real Workers and a controlled model over loopback HTTP;
    a separate Projection Worker SIGKILL probe (private development evidence; not distributed)
    passed on one controlled envelope with natural lease reclaim and no
    duplicate endpoint/IP observation; a
    Collector Worker SIGKILL probe (private development evidence; not distributed)
    passed with two real processes, stale-token denial, and one normalized
    terminal/IP observation;
    production CA/mTLS, API/database restart, cancellation, and live action
    recovery, plus real-device Collector recovery, remain for the lab.
14. **Scale sample** — run the representative PostgreSQL load plan against the
    number of lab devices available, record report/version/settings, and keep the
    production-sizing 1,000-target gate open until dedicated hardware is
    available. A private development-host PostgreSQL run has passed all
    functional 1,000-target harness gates, but it used synthetic targets and
    did not test exporter traffic. Separate Collector and Projection
    process-kill probes each used only one controlled envelope.
15. **Governed report delivery** — publish a scoped service-health Report and
    schedule Workflow through Studio; activate an exact Report version and a
    separately governed MCP adapter using explicitly approved test recipients.
    Verify that an occurrence is first labeled as Investigation dispatch, that
    delivery waits for independent approval, and that producer plus subsequent
    successful post-check evidence creates a receipt with both ToolCall IDs and
    times. Force a declared business post-check failure, approve the exact
    rollback, and confirm no receipt claims success. Download JSON through the
    Web UI, recompute its documented digest, test cross-namespace denial, and
    confirm that no report body, raw Tool result, or credential is exported.
    Older migrated receipts must remain visibly unverified. Retain the ledger
    and referenced execution evidence in backups; export is not purge approval.
16. **Saved report documents** — publish a real scoped Report, capture its exact
    version through `/reports`, and verify idempotent retry returns the same
    original snapshot. Change observations and confirm saved history/exports
    remain unchanged while live preview updates. Download PDF/HTML/CSV/JSON,
    recompute the documented JSON snapshot digest and each document-byte digest,
    check Chinese titles, long sections, no-data/drift states and safe text cells.
    Move current service ownership and test loss/new grant of read and export
    access; repeat with non-default tenant/region and hidden cursor IDs. A
    deprecated version must stay historical data but reject fresh capture.
    Verify installed-wheel PDF rendering without source-tree assets. Browser
    fixtures and SQLite migration tests do not satisfy live PostgreSQL RLS,
    concurrent idempotency or real data-quality acceptance. Retain instances
    and referenced version data in backups; no capture/export authorizes purge.

## Vendor-specific input required

  with all credentials removed before upload;
